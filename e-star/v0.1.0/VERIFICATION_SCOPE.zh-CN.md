# E* 验证范围拼图：公开记录、实际执行与尚未覆盖

版本1.0，2026-11-19。对应[论文与复现包e-star-v0.1.0](https://doi.org/10.5281/zenodo.24342987)。本说明补充验证范围，不改变原论文结论、原PDF、ZIP或其版本。

**“文件已列出”“发布方运行过”“别人独立复现了”“主定理已经完整形式化”，是四件不同的事。** 这份拼图把它们分开，避免从一个局部PASS跳到整篇论文验收。

## 1. 用户提供的评估，亲自核实到了哪里？

用户提供的一份评估摘录说：它能读取GitHub、Zenodo的公开记录，并对照原作者论文的HTML；但论文PDF与复核ZIP下载没有成功，因此没有独立重算哈希、执行测试或重跑Lean。

这应标为**对公开记录的范围评估**。摘录反复出现的“逐行审稿结论”前缀，不能覆盖它自己声明的访问限制；该摘录没有提供E*论文全文逐行审查或完整技术复现的证据。重复粘贴也不能算多位审阅者或多次验证。

| 项目 | 发布方已有记录 | 这份评估自述的核实范围 | 可准确得出的结论 |
| --- | --- | --- | --- |
| 匿名论文 | 8页PDF已编译、检查并公开 | 确认公开页面列出文件；未成功下载该PDF | 页面列出不等于评估者已读完论文 |
| 复现ZIP与清单 | 固定版本、哈希清单、新目录解包记录 | 确认Zenodo列出；未成功下载ZIP或重算哈希 | 有公开材料，不等于评估者已验其字节 |
| 三组有限检查 | 发布方有实际命令、退出0和有界结果记录 | 仅能引用发布方报告，没有亲自执行 | 发布方实跑与评估者独立复跑分开登记 |
| 14条Lean声明 | 固定源码、实际检查、公理输出及有限组合模块重放记录 | 仅依据发布方公开说明 | 局部形式化已有执行记录，未形成这位评估者的独立运行证据 |
| 有限消重桥 | 对既有桥的独立重实现，完整覆盖有限消重命题 | 认为有价值但非首创；未运行源码 | 不能主张首次数学桥或首次形式化 |
| 主逆定理 | 纸面论证；没有端到端Lean主定理 | 指出尚未端到端形式化 | 不能写“全主逆定理已机器验收”；不因此直接判纸面证明错误 |
| 1/4极限 | 纸面上下界与极限组装；局部比值算术有Lean | 指出仍依赖纸面证明 | 比值比较不是完整极限的形式化 |
| 外部同行评审 | 尚未完成 | 将其列为待办 | 内部代理复核或网页评估不能代称同行评审 |

这份评估的下载失败不抹去发布方已有运行记录，也不证明所有人都不能下载。反过来，发布方过去曾下载成功，也不能改写这位评估者“本次没有下载、没有运行”的事实。

## 2. 14条声明，究竟是哪14条？

复现包里的三个Lean文件分别包含3、6、5条相关声明。计数包括辅助引理与推论；有些算术范围重叠。**14不是14个独立主成果，也不能换算成“论文已证明百分之多少”。**

### 3条条件算术：LevAssembly.lean

| 声明 | 实际编码和证明 | 没有编码或作为假设的部分 |
| --- | --- | --- |
| scaled_increment | 给定密度和参数不等式后，对min表达式作缩放的算术下界 | 无有限集B、jB或真实和集基数对象；未证明Lev定理 |
| triple_sumset_card_bound | 假设n、n₂、n₃满足两步增长下界，推出n₃≥3L/2＋4 | 两步增长式h₂、h₃是输入；n₂、n₃只是实数参数，没有由代码证明它们等于真实和集基数 |
| triple_central_radius | 从给定基数下界推出中心余量表达式的上界 | 未证明该基数输入，也未证明区间被和集覆盖 |

例如第二条的正确说法是：“**如果两步增长事实成立，最后的代数下界推导已由Lean检查。**”不能说“Lean已从集合B出发证明完整的三重和集定理”。

### 6条算术接口：LevChain.lean

| 声明 | 已核验的接口 | 不能由名称外推的结果 |
| --- | --- | --- |
| min_step | 前提成立时，min的两端足以支持所用增量 | 不是和集增长定理本身 |
| normalized_density | 给定Gcard下界、余量和L≤E等输入，推出L/q＋2≤Gcard＋1 | 未构造好核、证明坏中心少或gcd归一化；Gcard是实数输入 |
| basis_window | 给定D、γ、J和y的条件，推出区间两端不等式 | 未证明区间元素属于真实和集；“位置在区间内”不等于“有求和表示” |
| theta_window | q≥4时，已知下端表达式不超过q−1 | 声明没有θ变量，不是θ_q≤q−1的完整证明 |
| ratio_upper | 给定T、ε条件下比较两个实数比值 | 没有F的全称上界、limsup或极限 |
| ratio_lower | T>0时比较构造大小的比值与1/4 | 没有构造避开目标/基数的组合证明，也没有liminf或极限 |

这些检查有助于排除算术错误，但不会自动建立输入的集合事实与量词关系。

### 5条有限组合声明：EStarDistinct.lean

| 声明 | 实际覆盖 |
| --- | --- |
| fresh_pair | 配对数大于占据值数时，有一对两端均未占据的中心配对 |
| support_increases | 两份重复中心换成两个新鲜互异端点后，支持集严格增大 |
| eliminate_repetitions | 对只有好中心可重复、总项数不超过m的多重集，得到同和同项数的无重复多重集 |
| distinct_sum_exact | 给定G⊆A、好中心配对条件和原G表示，得到同和、恰好原项数的互异A子集 |
| distinct_sum_nonempty | 再要求原项数>0，所得子集确实非空，排除空和边界 |

这个文件完整证明了修正后的**有限消重桥**，是比纯算术接口更具体的一块。它仍需输入“好中心足够好”“原目标已有重复表示”等前提；不能由此宣布从原A到最终主定理的所有前提都已编码。

发布方历史记录为：三份固定源码实际检查通过，公理输出仅为`propext, Classical.choice, Quot.sound`；EStarDistinct模块的新声明另经`leanchecker`重放。依赖缓存被复用，不是所有导入模块从零重建或全部闭包二次重放。本次补充只核对源码身份、签名与旧运行记录，没有新增一次Lean运行或替评估者完成独立复现。

## 3. 把主证明拼起来，还有哪些接口？

| 数学环节 | 纸面依据 | 本工程机器覆盖 | 未端到端编码的部分 |
| --- | --- | --- | --- |
| A很密→坏中心少→好核G足够大 | Roth、坏中心超图估计与既有框架 | 小集合检查；后续密度的部分算术 | Roth与概率估计、好核构造的全称组装 |
| G→gcd小于q→可整除目标→归一化B | 正整数gcd、最小非因子及归一化 | 有限gcd边界检查、部分密度算术 | 整段集合/整除组装 |
| B→多重和集密度→有界基覆盖 | Lev1996＋中心覆盖；也可直接用Lev1997 | 增长、区间算术及有限构造 | 所有q下的真实集合覆盖与表示存在 |
| 有界基→目标重复表示 | 目标窗口、整除、零填充与回乘 | 有限表示样本、部分窗口算术 | 将前序存在性前提统一连起来 |
| 重复表示→互异非空表示 | 好中心配对与良基量 | **完整有限消重桥的Lean证明** | 前序论证仍需实际建立桥的全部输入 |
| 逆定理→同一θ_q及1/4极限 | 长度界、分段上界、构造下界和极限量词 | θ/比值算术及有限构造 | θ定义、F全称界、阈值、limsup/liminf及最终合并 |

主结论当前是**引用既有数学输入的纸面证明**，有内部终审与有限/局部机器核验，尚待外部数学审阅。没有完成端到端Lean不自动否定纸面证明；局部Lean通过也不能替代尚未编码的主证明。

## 4. 拼图不是一张“可信度总分表”

| 证据维度 | 能回答的问题 | 不能替代的工作 |
| --- | --- | --- |
| DOI、版本、哈希与下载读回 | 拿到的文件是哪一版、字节是否一致？ | 数学正确性、作者身份或优先权 |
| 原文核读及前提对照 | 引用哪个定理、是否按相同前提使用？ | 把外部定理在本工程重新形式化 |
| 有限测试及负控制 | 所列有限输入是否通过？检查器能否暴露某些错误？ | 全部整数范围、未知阈值或无穷极限的证明 |
| 局部Lean与模块重放 | 被编码的具体声明在这些前提/依赖下是否通过？ | 没编码的组合接口及主定理 |
| 纸面推导和内部复核 | 主论证各接口是否有明确推导？ | 外部同行审稿意见 |
| 文献比较 | 在实际核过的版本和读集中，既有成果与本稿关系是什么？ | 全部先行工作排除、历史新颖性或优先权认证 |
| 场景/工程验证 | 实际数据、约束、误差和运行表现如何？ | 不能由加法示意或定理存在性直接填满；本稿未做工程实证 |

本次补充提高的是**范围透明度**，不是凭说明文字增加数学证明覆盖。核验块越多，越需要检查接口，而不是把所有PASS相加成整体验收。

## 5. 怎样完成一次真正有范围的独立复现？

1. 固定版本，从发布入口实际下载PDF与ZIP；记录成功/失败及时间，不把“页面列出”当下载。
2. 在自己环境计算SHA-256，与同一版本清单比较；这一步只确认字节。
3. ZIP解到新目录，执行`verify_manifest.py`和`run_checks.py`；保留解释器版本、命令、退出码、结果和有限覆盖范围。
4. 如需Lean复现，按README使用固定Lean/Mathlib版本和现成依赖；运行三份源码、核对定理签名与公理输出。模块重放和依赖缓存的信任边界另记。
5. 再独立阅读论文的量词、集合事实、外部输入和最终极限。程序复现与数学审阅是两种不同工作，不能把其中一种改名为另一种。

若只能完成前一两步，就如实报告已经完成的部分。对于用户提供的这份摘录，准确状态是“公开记录与相关HTML对照已做，但PDF/ZIP未下载，哈希/测试/Lean独立执行未做”，不是完整技术复现。
